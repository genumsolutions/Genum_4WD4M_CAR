## What this round owed the CAR repo

The owner's report (2026-10-24/25): **"webpage shows white screen in browser
and the ip is not hidden anywhere … fix these when webpage is off and make
things sensible."**

The app half (hiding the broadcast IP on every surface — chip + Control
address — and the never-truthful `carPageServing` ref) is the app repo. The
**car half is ONE line**:

- **Root cause (source-traced):** `serveGhostPage()` — the response a browser
  gets while the Webpage toggle is OFF — called
  `server.send(200, "text/html; charset=utf-8", "")`, which declares
  **`Content-Length: 0`** (the empty body string), and then wrote the ghost
  HTML *past* that declared length. The browser honoured the 0, stopped
  reading, and rendered **nothing** — the owner's white screen. The message
  the ghost page exists to show ("The car's web page is turned off…") never
  reached the screen.
- **Fix:** `server.setContentLength(len);` **before** the same `send(...)` —
  the exact contract `serveRootBounded()` already keeps for the 18 kB control
  page. No behaviour change beyond the header.
- **File:** `WebServerComm.cpp` (`serveGhostPage`), comment carries the owner
  quote and the reason.

Nothing else in the firmware was touched: 1.3.17's heap-gated connect path
and its green gates stand as written.
