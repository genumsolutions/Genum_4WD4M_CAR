## Part B — defects to fix in this round

### B1. The car's page overflows to the right
`WebPage.h` landscape `.side` rows use `justify-content:space-between` without the
`min-width:0` / overflow clipping the portrait rule has, so a long SSID, IP or
`REPLY=` grows past the column instead of ellipsising.
**Fix:** same edit as the 2WD1M — clip and ellipsise every landscape row.

### B2. Speed slider alignment
`.range-wrap` keeps a `flex:1` track beside a `34px` thumb and fixed-width value
columns, and drops `margin` in landscape; the thumb centre overhangs the track ends.
**Fix:** same edit as the 2WD1M — thumb-width side padding on the track, one
baseline for the value/limit columns.

### B3. D-pad landscape position
Left as-is this round: S-16 deliberately moved each pad to its half's outer edge.
"Standard position" could mean the opposite, so it is NOT changed without a word
from the owner (changing it back would undo a standing ruling).

### B4. "It connects once, then doesn't respond" — THE defect specific to this car
This was the reported fault for this car. `SerialBT.hasClient()` can stay latched
after the phone is gone, so `connected()` never went false: the own AP stayed
parked, `link_cap` stayed 0 (so the app refused the sibling) and the
`BT_HARD_RESTART_MS` watchdog never got the false edge it needed.

**Fixed this round (1.3.22, U-142):** the liveness proof is TX progress, not
`hasClient()`. `ModeManager` writes `STATE` every `STATE_INTERVAL_MS` (1.5 s) and
`BluetoothSerial::write()` returns 0 when the SPP channel is really closed, so a
socket that accepts nothing for `BT_SPP_TX_STALL_MS` (30 s) is reported DOWN. That
releases the AP park (~4 s) and lets the watchdog re-init BT — recovery without a
power cycle. Bench rows U-142-1..6 in `DEVICE-TESTS.md`, including the guard that
an idle-but-live link is never declared stalled.
